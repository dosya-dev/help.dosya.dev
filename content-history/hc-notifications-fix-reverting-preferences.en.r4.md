This guide covers **Fix notification preferences that revert** in Dosya. The main action is to change one setting, wait for confirmation, reload, and check account, role, and network state if it reverts; the decisive check is whether the saved value persists or the blocking condition is identified.

## Before you start

- Open Profile > Notifications and the notification inbox in the current released client.
- Confirm the active account and workspace, then identify preference that does not remain saved.

## Steps: fix notification preferences that revert

1. Open Profile > Notifications and the notification inbox and confirm the active account and workspace.
2. Locate preference that does not remain saved and verify its name or identifying details.
3. Change one setting, wait for confirmation, reload, and check account, role, and network state if it reverts.
4. Confirm that the saved value persists or the blocking condition is identified.

**Safety note.** Keep security notifications enabled and test optional channels with a harmless event.

## Verify the result

After completing the steps, check the expected result: The saved value persists or the blocking condition is identified.

## Expected result

The controlled workflow completes and the saved value persists or the blocking condition is identified.

## Troubleshooting

**The expected control is missing.** Return to Profile > Notifications and the notification inbox, confirm the active workspace, and check that your role and client version support the action.
