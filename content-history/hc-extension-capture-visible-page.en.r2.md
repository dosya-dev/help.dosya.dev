## Before you start

- Open the Save to Dosya browser extension in the current released client.
- Confirm the active account and workspace, then identify browser tab and screenshot capture option.
- Use a small non-confidential test item and record its current state before changing it.
- Keep passwords, API keys, recovery keys, private links, personal data, and confidential file contents out of screenshots and support messages.

## Steps: capture the visible page with the extension

1. Open the Save to Dosya browser extension and confirm the active account and workspace.
2. Locate browser tab and screenshot capture option and verify its name or identifying details.
3. Arrange the visible area, remove private overlays, choose screenshot capture, and save.
4. Read the displayed warning, permission, progress, or confirmation state before leaving the screen.
5. Confirm that Dosya stores a screenshot of the reviewed visible content.
6. Refresh, fetch, or reopen the relevant view once to verify the result persisted.

## Troubleshooting

**The expected control is missing.** Return to the Save to Dosya browser extension, confirm the active workspace, and check that your role and client version support the action.

**The operation is rejected or stalls.** Read the exact message and check permissions, locks, storage, network state, source availability, and any third-party authorization before retrying.

**The result is still unclear.** Repeat with one small test item, then contact support with the time, client version, workspace, and a nonsecret error, delivery, or request identifier.
