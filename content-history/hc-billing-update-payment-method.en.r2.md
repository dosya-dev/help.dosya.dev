This guide covers **Update a payment method in the billing portal** in Dosya. The main action is to verify the account and plan, add or choose the intended payment method, save it, and return to Dosya billing; the decisive check is whether the portal shows the intended method for future eligible charges.

Keep the signed-in account, security state, plan, billing period, and saved preference in view while you work. Use step 2 to identify the exact target, then record its current state so a refresh, reconnect, or return to the page gives you a reliable comparison.

## Before you start

- Open Account settings > Billing in the current released client.
- Confirm the active account and workspace, then identify authorized billing portal session.
- Use a small non-confidential test item and record its current state before changing it.
- Keep passwords, API keys, recovery codes, private links, personal data, and confidential file contents out of screenshots and support messages.

## Steps: update a payment method in the billing portal

1. Open Account settings > Billing and confirm the active account and workspace.
2. Locate authorized billing portal session and verify its name or identifying details.
3. Verify the account and plan, add or choose the intended payment method, save it, and return to Dosya billing.
4. Read the displayed warning, permission, progress, or confirmation state before leaving the screen.
5. Confirm that the portal shows the intended method for future eligible charges.
6. Refresh, fetch, or reopen the relevant view once to verify the result persisted.

## Verify the result

After completing the steps, check the expected result: The portal shows the intended method for future eligible charges. Do not rely only on a success toast or submitted request. Refresh or reopen the relevant view and compare the visible account, workspace, path, status, count, or permission with the state you recorded before the task.

Reopen the relevant account page and confirm the displayed value belongs to the intended account. If the result differs from what you expected, stop before repeating the action. Capture the time and nonsecret status, then check session, verification, billing, or policy requirements before trying again.

## Expected result

The controlled workflow completes and the portal shows the intended method for future eligible charges. The result remains visible after a refresh, reconnect, or return to the relevant screen.

## Limits and important details

- Available controls depend on the current client version, account plan, workspace role, policy, and selected integration surface.
- Processing, indexing, background transfer, provider authorization, or storage accounting can delay a visible result.
- For destructive, access-changing, or automated actions, validate with disposable data before applying the workflow to important files.

## Practical checks

- Confirm you are working in the intended account and workspace before selecting the target.
- Re-read the exact target name, folder path, member, endpoint, or provider shown by the interface.
- Complete one controlled example first when the action can affect access, create copies, move data, or start a transfer.
- Verify the final state after a refresh; keep only nonsecret timestamps, statuses, and request identifiers for support.

## Troubleshooting

**The expected control is missing.** Return to Account settings > Billing, confirm the active workspace, and check that your role and client version support the action.

**The operation is rejected or stalls.** Read the exact message and check permissions, locks, storage, network state, source availability, and any third-party authorization before retrying.

**The result is still unclear.** Repeat with one small test item, then contact support with the time, client version, workspace, and a nonsecret error, delivery, or request identifier.

## Frequently asked questions

### What should I check before repeating this task?

Return to the first step and confirm the active account, workspace, and target. Then compare the current state with the result described above. Repeating the action without that comparison can create duplicates, overwrite the wrong setting, or make the original error harder to diagnose.

### What details should I include when asking for help?

Include the action time, client or browser version, active workspace, expected result, visible status, and any nonsecret error or request identifier. Never include passwords, API keys, recovery codes, private sharing links, payment details, or confidential file contents.
