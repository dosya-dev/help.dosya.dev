This guide covers **Review duplicate names after a cloud import** in Dosya. The main action is to compare file details and the documented duplicate-name behavior before deleting or renaming anything; the decisive check is whether both source and existing content are understood.

## Before you start

- Open a completed or partially completed cloud import in the current released client.
- Confirm the active account and workspace, then identify destination containing pre-existing and imported same-name items.

## Steps: review duplicate names after a cloud import

1. Open a completed or partially completed cloud import and confirm the active account and workspace.
2. Locate destination containing pre-existing and imported same-name items and verify its name or identifying details.
3. Compare file details and the documented duplicate-name behavior before deleting or renaming anything.
4. Confirm that both source and existing content are understood.

## Verify the result

After completing the steps, check the expected result: Both source and existing content are understood.

## Expected result

The controlled workflow completes and both source and existing content are understood.

## Troubleshooting

**The expected control is missing.** Return to a completed or partially completed cloud import, confirm the active workspace, and check that your role and client version support the action.
