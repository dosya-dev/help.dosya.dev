This guide covers **Troubleshoot a text file that will not open for editing** in Dosya. The main action is to check file type, size, permission, lock state, and network status before retrying; the decisive check is whether the file opens in the supported editor or a specific limitation is identified.

## Before you start

- Open a supported text file in Dosya in the current released client.
- Confirm the active account and workspace, then identify file whose Edit control is missing or fails.

## Steps: troubleshoot a text file that will not open for editing

1. Open a supported text file in Dosya and confirm the active account and workspace.
2. Locate file whose Edit control is missing or fails and verify its name or identifying details.
3. Check file type, size, permission, lock state, and network status before retrying.
4. Confirm that the file opens in the supported editor or a specific limitation is identified.

**Safety note.** Keep an independent copy before making substantial edits to an important text file.

## Verify the result

After completing the steps, check the expected result: The file opens in the supported editor or a specific limitation is identified.

## Expected result

The controlled workflow completes and the file opens in the supported editor or a specific limitation is identified.

## Troubleshooting

**The expected control is missing.** Return to a supported text file in Dosya, confirm the active workspace, and check that your role and client version support the action.
