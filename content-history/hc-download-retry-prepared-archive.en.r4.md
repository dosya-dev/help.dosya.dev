This guide covers **Retry an expired prepared archive** in Dosya. The main action is to return to the original folder or selection and create a fresh archive instead of reusing the old temporary link; the decisive check is whether the new archive downloads from a current preparation job.

Track the newly prepared archive with its destination, available storage and transfer state.

## Before you start

- Open the Dosya file list and download controls in the current released client.
- Confirm the active account and workspace, then identify prepared archive link that is no longer available.

## Steps: retry an expired prepared archive

1. Open the Dosya file list and download controls and confirm the active account and workspace.
2. Locate prepared archive link that is no longer available and verify its name or identifying details.
3. Return to the original folder or selection and create a fresh archive instead of reusing the old temporary link.
4. Confirm that the new archive downloads from a current preparation job.

**Safety note.** Choose the smallest suitable download and verify the local result before distributing it.

## Verify the result

After completing the steps, check the expected result: The new archive downloads from a current preparation job.

Compare the newly prepared archive with its source by name, size and destination before removing a local copy. Record the exact transfer error for the newly prepared archive before retrying; check size, quota and destination.

## Expected result

The controlled workflow completes and the new archive downloads from a current preparation job.

## Troubleshooting

**The expected control is missing.** Return to the Dosya file list and download controls, confirm the active workspace, and check that your role and client version support the action.
