Use this workflow to track a failed file-request submission in the intended account or workspace.

The main checks are the share or request identity, recipient policy and destination. Test recipient access with non-confidential data and confirm that only the intended people and files are included.

## Before you start

- Open File request details in the current released Dosya client.
- Confirm the active account and workspace, then identify one controlled failed upload.

## Steps: track a failed file-request submission

1. Open File request details and confirm the active workspace.
2. Select one controlled failed upload and check its name or identifying details.
3. Review its error, limits and recipient status before retrying.
4. Verify that the retry either completes or provides a specific actionable error.

Verify that the retry either completes or provides a specific actionable error.

## Expected result

The workflow completes for the controlled test and the retry either completes or provides a specific actionable error.

## Troubleshooting

**The expected control is missing.** Return to File request details, confirm the active workspace and check that your role permits the action.
