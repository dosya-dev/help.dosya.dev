This guide covers **Document suspicious account activity for support** in Dosya. The main action is to record time, device, approximate location, affected resource, and nonsecret request details; the decisive check is whether support receives useful evidence without passwords, codes, or recovery keys.

## Before you start

- Open Profile > Security and Sessions in the current released client.
- Confirm the active account and workspace, then identify security event that still needs investigation.

## Steps: document suspicious account activity for support

1. Open Profile > Security and Sessions and confirm the active account and workspace.
2. Locate security event that still needs investigation and verify its name or identifying details.
3. Record time, device, approximate location, affected resource, and nonsecret request details.
4. Confirm that support receives useful evidence without passwords, codes, or recovery keys.

## Verify the result

After completing the steps, check the expected result: Support receives useful evidence without passwords, codes, or recovery keys.

## Expected result

The controlled workflow completes and support receives useful evidence without passwords, codes, or recovery keys.

## Troubleshooting

**The expected control is missing.** Return to Profile > Security and Sessions, confirm the active workspace, and check that your role and client version support the action.
