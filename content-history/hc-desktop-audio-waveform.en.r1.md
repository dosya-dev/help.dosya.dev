## Before you start

- Open a media preview in the Dosya desktop app in the current released client.
- Confirm the active account and workspace, then identify loaded audio waveform.
- Use a small non-confidential test item and record its current state before changing it.
- Keep passwords, API keys, recovery keys, private links, and personal data out of screenshots and support messages.

## Steps: seek with the desktop audio waveform

1. Open a media preview in the Dosya desktop app and confirm the active account and workspace.
2. Locate loaded audio waveform and verify its name or identifying details.
3. Select a known point and verify elapsed time.
4. Read the displayed warning, permission, progress, or confirmation state before leaving the screen.
5. Confirm that playback moves to the chosen position.

## Expected result

The controlled workflow completes and playback moves to the chosen position. The result remains visible after a refresh, reconnect, or return to the relevant screen.

## Limits and important details

- Available controls depend on the current client version, account plan, workspace role, and policy.
- Processing, indexing, background transfer, or third-party authorization can delay a visible result.
- For destructive, access-changing, or automation actions, validate with disposable data before applying the workflow to important files.

## Troubleshooting

**The expected control is missing.** Return to a media preview in the Dosya desktop app, confirm the active workspace, and check that your role and client version support the action.

**The operation is rejected or stalls.** Read the exact message and check permissions, locks, storage, network state, source availability, and any third-party authorization before retrying.

**The result is still unclear.** Repeat with one small test item, then contact support with the time, client version, workspace, and a nonsecret error or request identifier.
